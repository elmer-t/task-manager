# UI stack comparison for a Fluent Windows 11 task manager

- **Date:** 2026-07-15
- **Ticket:** [#2 — Compare candidate UI stacks for a Fluent Windows task manager](https://github.com/elmer-t/task-manager/issues/2)

## Question

Which UI stacks are viable for a personal Windows 11 task manager (Fluent look: Mica, system dark/light; live ~1 Hz time-series charts for CPU/memory; Windows API access for process/service/perf-counter data; doubles as a learning project), and how do they compare? Candidates: WinUI 3, WPF (+ Fluent theme), Avalonia, Tauri, Electron. Facts and trade-offs only — no final decision.

## Summary table

| Axis | WinUI 3 | WPF + Fluent | Avalonia | Tauri | Electron |
|---|---|---|---|---|---|
| Fluent fidelity out of the box | Reference implementation: real WinUI controls, `MicaBackdrop` one-liner, automatic theme fallbacks | Fluent theme built in since .NET 9 (`ThemeMode="System"`), but still work-in-progress and API is experimental | FluentTheme is a re-implementation; Mica via `TransparencyLevelHint` (Win11 only) | Window gets real Mica via effects API; page content is web — Fluent look must be rebuilt (e.g. Fluent UI web components) | Window gets real Mica via `backgroundMaterial` (Win11 22H2+); content is web, same rebuild caveat |
| Windows API friction | Lowest (C#: `Process`, `PerformanceCounter`, `ServiceController`, WMI, CsWin32) | Lowest (same .NET APIs) | Low (same .NET APIs; app itself stays cross-platform only if you isolate them) | Medium (Rust: `windows` crate, `sysinfo`; IPC layer between backend and UI) | Medium (Node: `systeminformation`, native modules/FFI; IPC layer) |
| Live charting | LiveCharts2, ScottPlot 5 (WinUI controls) | LiveCharts2, ScottPlot 5, OxyPlot — most mature .NET charting target | LiveCharts2, ScottPlot 5 (Avalonia controls) | Full web ecosystem: uPlot, ECharts, Chart.js, Lightweight Charts | Same web ecosystem |
| Learning value / ecosystem 2026 | Teaches current MS-native stack; WinAppSDK 2.x cadence, but community complaints about pace/openness persist | Teaches classic XAML/MVVM; actively invested again (Fluent work in .NET 9/10/11) but old technology | Teaches cross-platform XAML; very active OSS (12.1, Wayland backend) with commercial backing | Teaches Rust + web + IPC; active (2.11.x) | Teaches web-on-desktop; extremely mature, ~8-week major releases tracking Chromium |
| Dev loop | XAML Hot Reload + .NET Hot Reload in VS; **no XAML designer** | Best-supported XAML Hot Reload + designer in VS | IDE previewer + .NET Hot Reload (community); VS/Rider/VS Code | Vite HMR for UI (instant); Rust rebuild for backend changes | Fastest UI loop (web HMR); heaviest runtime |

## WinUI 3 (Windows App SDK)

- **Fluent fidelity: the benchmark.** WinUI 3 *is* the Windows 11 design system: Mica is a one-liner (`<Window.SystemBackdrop><MicaBackdrop/>`), with `MicaKind.BaseAlt`, `DesktopAcrylicBackdrop`, and per-element `SystemBackdropElement` (WinAppSDK 1.6.3+). Fallback for RDP, disabled transparency, battery saver, and high contrast is automatic. ([Materials in Windows apps](https://learn.microsoft.com/windows/apps/develop/ui/materials), [System backdrops](https://learn.microsoft.com/windows/apps/develop/ui/system-backdrops), [Mica material](https://learn.microsoft.com/windows/apps/design/style/mica)) Mica requires Windows 11; falls back to solid theme color on Windows 10 — irrelevant here (Win11 target). The [recommended app structure](https://learn.microsoft.com/windows/apps/develop/ui/windows-app-sdk-app-structure) (Mica + custom title bar + `NavigationView` + transparent page backgrounds) is exactly the Task-Manager-style shell.
- **Windows APIs:** full .NET — `System.Diagnostics.Process`, [`PerformanceCounter`](https://learn.microsoft.com/dotnet/api/system.diagnostics.performancecounter) (Windows-only `System.Diagnostics.PerformanceCounter` package), [`ServiceController`](https://learn.microsoft.com/dotnet/api/system.serviceprocess.servicecontroller), WMI via `System.Management`, and source-generated P/Invoke via [CsWin32](https://github.com/microsoft/CsWin32). No IPC boundary: the UI thread and the data collectors live in one process (dispatch to `DispatcherQueue` for UI updates).
- **Charting:** [LiveCharts2](https://github.com/Live-Charts/LiveCharts2) (SkiaSharp-based, WinUI package) and [ScottPlot 5](https://scottplot.net/) (WinUI control, ["Plot live, changing data" FAQ](https://scottplot.net/faq/live-data/); API nearly identical across WPF/WinUI/Avalonia). 1 Hz updates are trivial for either.
- **Ecosystem 2026:** current stable Windows App SDK is 2.x (2.2.0 as of mid-2026) with regular stable-channel releases ([release channels](https://learn.microsoft.com/windows/apps/windows-app-sdk/release-channels), [GitHub releases](https://github.com/microsoft/WindowsAppSDK/releases)). It is Microsoft's designated native UX framework, but longstanding community criticism about development pace and openness of the WinUI repos has not fully disappeared — worth knowing for a learning bet.
- **Dev loop:** XAML Hot Reload + Live Visual Tree + Live Property Explorer + XAML Live Preview in Visual Studio ([runtime design tools](https://learn.microsoft.com/windows/apps/develop/ui/xaml-runtime-design-tools)). Notable gap: **the drag-and-drop XAML Designer does not support WinUI 3** ([tracked request](https://developercommunity.visualstudio.com/t/add-xaml-designer-support-for-winui-3-desktop-apps/1496648)) — you write XAML by hand and iterate with Hot Reload. Best experience is Visual Studio on Windows; Rider/VS Code work but with less XAML tooling. Deployment: packaged (MSIX) or unpackaged; .NET trimming supported.

## WPF + Fluent theme (.NET 9/10)

- **Fluent fidelity: good and improving, not finished.** .NET 9 shipped a first-party Fluent theme with light/dark and accent-color support, applied via `ThemeMode="System"` or the `PresentationFramework.Fluent` resource dictionary ([What's new in WPF for .NET 9](https://learn.microsoft.com/dotnet/desktop/wpf/whats-new/net90)). Setting `ThemeMode` also applies the backdrop and dark mode to the window ([Window.ThemeMode](https://learn.microsoft.com/dotnet/api/system.windows.window.thememode?view=windowsdesktop-10.0)). Caveats: the `ThemeMode` API is **experimental** (`WPF0001` must be suppressed to set it in code, "may be removed in future versions"), and Microsoft's own .NET 10 notes say "Fluent UI style support is still in progress" — .NET 10 added Fluent styles for DatePicker, GridSplitter, GridView, GroupBox, Label, TextBox, RichTextBox etc. and fixed HighContrast crashes ([What's new in WPF for .NET 10](https://learn.microsoft.com/dotnet/desktop/wpf/whats-new/net100)); .NET 11 previews continue DWM/Fluent bug fixes ([What's new in WPF](https://learn.microsoft.com/dotnet/desktop/wpf/whats-new/)). Third-party WPF-UI-style libraries can fill gaps. Microsoft's FAQ explicitly positions .NET 9+ WPF as able to "match the sleek, modern look of Windows 11" ([Windows developer FAQ](https://learn.microsoft.com/windows/apps/get-started/windows-developer-faq)).
- **Windows APIs:** identical to WinUI 3 — full .NET surface, no IPC. The best-trodden path of all candidates (decades of Stack Overflow answers on perf counters, WMI, services).
- **Charting:** the richest .NET charting target: LiveCharts2, ScottPlot 5 ([WPF quickstart](https://scottplot.net/quickstart/), live-data patterns documented), OxyPlot. Most .NET charting docs assume WPF first.
- **Ecosystem 2026:** open source ([dotnet/wpf](https://github.com/dotnet/wpf)), actively invested again after years of maintenance mode — .NET 10 brought measurable performance work, `Grid` short-hand syntax, 4,000+ new tests ([.NET 10 notes](https://learn.microsoft.com/dotnet/desktop/wpf/whats-new/net100)). Windows-only by design. Learning value: teaches XAML/MVVM/bindings that transfer to WinUI/Avalonia/MAUI, but it is 20-year-old technology at its core.
- **Dev loop: the most polished XAML experience.** XAML Hot Reload is fully supported (WPF is its original target), plus the visual XAML Designer, Live Visual Tree, and design-time Hot Reload since VS 17.14 ([XAML Hot Reload](https://learn.microsoft.com/visualstudio/xaml-tools/xaml-hot-reload)). Works in VS and Rider.

## Avalonia

- **Fluent fidelity: convincing approximation, not pixel-identical.** Ships `FluentTheme` (Fluent v2-based, light/dark) as the default theme. Mica works on Windows 11 via `TransparencyLevelHint="Mica"` + `Background="Transparent"`, with graceful fallback ordering, e.g. `"Mica, Blur"` ([TopLevel docs](https://docs.avaloniaui.net/docs/concepts/toplevel), [WindowTransparencyLevel](https://docs.avaloniaui.net/api/avalonia/controls/windowtransparencylevel), [Windows platform guide](https://docs.avaloniaui.net/docs/platform-specific-guides/windows)). Controls are Avalonia's own drawn implementations — close to WinUI in spirit, not identical in metrics/animations; system dark/light following is supported via `RequestedThemeVariant` default.
- **Windows APIs:** it's .NET, so the same `Process`/`PerformanceCounter`/`ServiceController`/WMI/CsWin32 story as WPF/WinUI, in-process. The cross-platform promise is moot for Windows-only data sources unless the Windows-specific collectors are isolated behind interfaces (which is itself a good learning exercise).
- **Charting:** LiveCharts2 has a first-class Avalonia package ([LiveChartsCore.SkiaSharpView.Avalonia](https://www.nuget.org/packages/LiveChartsCore.SkiaSharpView.Avalonia/)); ScottPlot 5 ships an Avalonia control ([quickstart](https://scottplot.net/quickstart/avalonia/)). Both handle 1 Hz streaming comfortably.
- **Ecosystem 2026: very active.** Avalonia 12 / 12.1 shipped with a native Wayland backend, new `TableView` control, hit-testing and rendering-allocation rework ([Avalonia 12 announcement](https://avaloniaui.net/blog/avalonia-12), [12.1 release post](https://avaloniaui.net/blog/release-12-1), [releases](https://github.com/AvaloniaUI/Avalonia/releases)). MIT-licensed OSS backed by a company selling commercial add-ons (XPF, Accelerate) — sustainable but means some tooling is paid. Large adoption (e.g. UniGetUI migrated to it in 2026).
- **Dev loop:** XAML previewer in VS/Rider/VS Code extensions; .NET Hot Reload works for code, XAML hot reload is via community extension rather than a first-party VS feature — a step below WPF/WinUI's integrated XAML Hot Reload. Rider and VS Code are first-class citizens, not just VS.

## Tauri (v2)

- **Fluent fidelity: real Mica window, simulated Fluent content.** The window backdrop can be genuine Mica/Acrylic via the window effects API (`WindowEffect::Mica` in config or `setEffects` from JS; Mica is Windows 11-only, Acrylic 10/11) with `"transparent": true` required ([window customization](https://v2.tauri.app/learn/window-customization/), [JS window API](https://v2.tauri.app/reference/javascript/api/namespacewindow/), [tauri-apps/window-vibrancy](https://github.com/tauri-apps/window-vibrancy)). Everything inside the window is HTML/CSS rendered by WebView2 — Fluent controls, dark/light switching, Segoe Fluent Icons, and scrollbars must be recreated (Microsoft's [Fluent UI web components](https://github.com/microsoft/fluentui) get close, not exact). WebView2 means the actual Chromium engine is the OS-serviced Edge runtime, so app binaries stay small (single-digit MB).
- **Windows APIs: two-language architecture.** Data collection happens in the Rust backend — [`windows`](https://github.com/microsoft/windows-rs) crate (official Microsoft Win32/WinRT bindings), [`sysinfo`](https://crates.io/crates/sysinfo) for cross-platform process/CPU/memory basics — then crosses Tauri's IPC (commands/events) to the JS frontend. That IPC hop at 1 Hz is trivial for performance but is real design/serialization work, and service/perf-counter access means Rust FFI territory rather than a managed API.
- **Charting:** the entire web ecosystem: [uPlot](https://github.com/leeoniya/uPlot) (built exactly for fast streaming time-series, ~50 KB), Chart.js, Apache ECharts, TradingView Lightweight Charts. Arguably the strongest pure-charting options of any stack; 1 Hz is nothing.
- **Ecosystem 2026:** Tauri 2.x stable since Oct 2024, steady patch cadence (2.11.x as of July 2026) ([releases](https://github.com/tauri-apps/tauri/releases), [Tauri 2.0 announcement](https://v2.tauri.app/blog/tauri-20/)). Governed by a Dutch non-profit (Tauri Programme within the Commons Conservancy). Learning value is high but split across two stacks: Rust + async + IPC design, and a web frontend.
- **Dev loop:** `tauri dev` gives instant Vite/HMR iteration on the UI; changes to Rust backend code require a Rust recompile (incremental, but Rust compile times are the known tax). Tooling is VS Code-centric (rust-analyzer + your web tooling), not Visual Studio.

## Electron

- **Fluent fidelity: same shape as Tauri.** `BrowserWindow`'s `backgroundMaterial: 'mica' | 'acrylic' | 'tabbed' | 'auto' | 'none'` gives a real system backdrop, **Windows 11 22H2+ only** ([BrowserWindow docs](https://www.electronjs.org/docs/latest/api/browser-window)). Content is Chromium-rendered web UI, so Fluent controls/dark-light theming are rebuilt in HTML/CSS (Fluent UI React/web components approximate). Unlike Tauri, Electron bundles its own Chromium + Node, so a minimal app is roughly 80-100+ MB on disk with higher baseline memory — notable for an always-running monitoring tool.
- **Windows APIs:** the [systeminformation](https://github.com/systeminformation/systeminformation) npm package covers processes/CPU/memory/services out of the box; anything deeper (perf counters, ETW) means native Node addons (N-API/node-gyp) or FFI (koffi) — the highest-friction path of the five for *Windows-specific* depth, though the common metrics are one `npm install` away. Same main-process/renderer IPC boundary as Tauri (`ipcMain`/`ipcRenderer`).
- **Charting:** identical web ecosystem to Tauri (uPlot, ECharts, Chart.js, Lightweight Charts).
- **Ecosystem 2026: the most battle-tested of the five.** Major release every ~8 weeks tracking Chromium (Electron 43 stable as of July 2026; three most recent majors supported) ([release timelines](https://www.electronjs.org/docs/latest/tutorial/electron-timelines), [releases.electronjs.org](https://releases.electronjs.org/)). OpenJS Foundation governance; VS Code, Slack, Discord etc. built on it. Learning value: transferable web/Node skills, little Windows-native learning.
- **Dev loop:** the fastest UI iteration of all (webpack/Vite HMR, Chromium DevTools built in); main-process changes need an app restart. Tooling is VS Code/web-standard.

## Cross-cutting notes

- **The Fluent split is structural:** the three .NET stacks draw Fluent-styled *native controls* (WinUI = the real thing; WPF = first-party theme still maturing; Avalonia = independent re-implementation), while the two web stacks get a genuine Mica *window* but simulate Fluent *content* in HTML/CSS. If "indistinguishable from Windows 11 Settings/Task Manager" is the bar, only WinUI 3 clears it without extra work — Windows 11's own Task Manager is XAML Islands/WinUI-based.
- **IPC boundary vs. single process:** the .NET stacks poll perf counters and update charts in one process. Tauri and Electron require designing a backend-to-frontend message channel for every metric stream — fine at 1 Hz, but it is permanent architecture, and it doubles the surface for a learning project (which cuts both ways: more to learn, slower to ship).
- **Perf-counter gotcha (all .NET stacks):** `PerformanceCounter` is Windows-only and first-read-returns-zero for rate counters; WMI (`System.Management`) is also Windows-only. This is friction *within* .NET, identical across WinUI/WPF/Avalonia, so it does not differentiate them.
- **Footprints (rough order):** Tauri smallest (OS WebView2), then the .NET stacks (framework-dependent deploys are small; self-contained ~70-100 MB but single-process), Electron largest (bundled Chromium, multi-process).
- **Learning-project angle:** WinUI 3 teaches "modern Windows native" but with designer-less tooling; WPF teaches the most-documented XAML dialect on the easiest tooling; Avalonia adds cross-platform architecture discipline; Tauri adds Rust and IPC design; Electron mostly reuses web skills.
